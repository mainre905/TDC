## 2. 히트 신호의 정체 — FMCW 보조 간섭계의 비트 신호다

### 2-1. CH1 은 사인파다

CH1 을 연속 표본으로 보면 매끄러운 정현파다. (앞서 이 문서 초판에서 "잡음"이라고 쓴 것은
**435 표본 간격으로 뽑아 놓고 파형이라 읽은 오독**이었다. 67 kHz 사인을 43 µs 마다 뽑았으니
앨리어싱되어 잡음처럼 보였던 것이다.)

| 항목 | 값 |
|---|---|
| 스펙트럼 에너지가 40~110 kHz 대역에 모인 비율 | **96.4 %** (잡음이면 넓게 퍼진다) |
| 1 ms 안의 완전한 주기 수 | **67 주기** → 평균 **67.5 kHz** |
| 피크 진폭 | 0.16 V |
| 영교차에서의 기울기 | `2πfA` = **71.7 mV/µs** |

### 2-2. 비교기는 그 사인파의 영교차마다 반전한다

| | 개수 |
|---|---|
| CH1 영교차 (1 ms) | **135개** (영 근처에서 1 µs 안에 되돌아온 잡음성 재교차 21개 제외) |
| LVDS 극성 반전 (1 ms) | **134개** |

**1 영교차 : 1 반전, 정확히 일치한다.** 듀티가 50.2 % 인 것도 사인파를 0 V 기준으로
자른 결과 그대로다. `corr(CH1, sign(CH4−CH3)) = −0.59` 는 **−2/π = −0.637** 에 가까운데,
이것이 바로 **사인파를 비교기로 각지게 만들었을 때 나오는 값**이다 (부호는 반전을 뜻함).

> **아직 설명 못한 것**: LVDS 에지가 CH1 영교차보다 평균 **1.9 µs 앞선다**(표준편차 0.67 µs,
> 상승·하강 양쪽 모두 같은 방향). 비교기가 입력보다 먼저 반응할 수는 없으므로, **CH1 을 찍은
> 지점이 비교기가 실제로 비교하는 노드가 아니거나** 기준 전압이 0 V 가 아니라는 뜻이다.
> 100 ns 표본 간격 데이터로는 더 못 좁힌다. → **비교기 입력 핀에서 빠른 시간축으로 다시 잴 것.**
> 1:1 대응 자체에는 영향이 없다.

### 2-3. 그리고 그 사인파는 chirp 하고 있다 — 이게 측정 대상이다

영교차 간격에서 **순간 비트 주파수**를 뽑으면 톱니 모양이다.

```
t(us)  -496 ... -300 ... -203  -178   -170 ... -100 ...   +2 ...  +303  +318   +329 ...  +490
f(kHz)  64      80       86    (전환)  34      56         68       82   (전환)  36       67
        └────────── 상승 ──────────┘         └──────────── 상승 ────────────┘        └── 상승 ──
```

| 항목 | 값 |
|---|---|
| 한 chirp 안에서 비트 주파수 | **34 → 86 kHz** (약 2.5배 변함) |
| 전환(flyback) 시각 | t ≈ −180 µs, +315 µs |
| **chirp 주기** | **약 495 µs → 반복률 약 2.0 kHz** |

FMCW 에서 보조 간섭계의 비트 주파수는 `f_beat = (dν/dt) × τ_aux` 이고 `τ_aux` 는 고정이므로,
**비트 주파수의 변화 = 레이저 소인율(chirp rate)의 비선형성**이다. 보조 간섭계는 바로 그것을
재려고 있는 것이고, **TDC 의 임무는 그 영교차 하나하나에 시각을 찍는 것**이다.

### 2-4. ILA 데이터에도 같은 chirp 이 그대로 보인다

`mode2.csv` 에서 한 위상 스텝 안의 16발은 연속된 영교차다. 그 간격을 늘어놓으면:

```
step 41 간격(us): 12.83 12.72 [38.05] 23.85 20.32 18.37 17.55 16.76 16.34 15.75 15.32 15.11 14.68 14.62 14.17
step 81 간격(us): 12.50 12.72  14.55 [25.95] 23.48 20.19 18.60 17.14 16.71 16.28 15.86 15.35 14.78 14.61 14.59
```

대괄호가 **flyback**(전환점에서 비트가 죽어 간격이 벌어지는 자리)이고, 그 뒤로 간격이
**단조 감소**한다 — 24 µs(42 kHz) → 14 µs(71 kHz). **스코프가 본 것과 같은 chirp 이다.**

> **그래서 이 데이터로는 TDC 의 지터를 못 잰다.** 스텝 안 16발에 3~7차 다항식을 맞춰 잔차를
> 봤더니 1.0~3.4 µs 가 나왔는데, 이건 지터가 아니라 **다항식이 flyback 불연속을 못 따라가서
> 생긴 모델 오차**다. 지터를 재려면 flyback 이 끼지 않은 구간에서 연속으로 캡처해야 한다.

### 2-5. LVDS 진폭에 대한 앞선 가설은 철회한다

| 항목 | 값 |
|---|---|
| 공통모드 `(CH3+CH4)/2` | +1.211 V (LVDS 규격 1.125~1.375 V, 정상) |
| 차동 `CH4−CH3` | ±615 mV (LVDS 규격 247~454 mV) |

앞서 이 진폭을 근거로 **J18 점퍼가 1.8 V 일 가능성**을 의심했는데, **철회한다.**
이 측정은 **100 Ω 종단 없이 스코프 1 MΩ 입력**으로 이뤄졌다. 전류구동 LVDS 드라이버가
종단 없이 고임피던스를 보면 진폭이 커지는 것이 정상이므로, **615 mV 는 측정 조건의 결과이지
보드 이상의 증거가 아니다.** J18 상태는 이 데이터로 판단할 수 없다 — 실물로 확인할 사항이다.

### 2-6. 이 캡처가 분해할 수 있는 시간 한계

스코프의 CH1 양자화 계단이 약 4.1 mV 이고 영교차 기울기가 71.7 mV/µs 이므로,

```
타이밍 분해 한계 = 4.1 mV / 71.7 mV/us = 약 57 ns
```

TDC 의 1 LSB 는 약 **0.0156 ns** 다. **이 스코프 캡처는 TDC 보다 약 3,600배 거칠다** —
1:1 대응을 확인하는 데는 충분하지만, 타이밍 품질을 논하는 데는 쓸 수 없다.

## 3. TDC 하드웨어 경로는 정상이다

### 히트가 제대로 들어오고 있다

`RTL/tdc_fmcw_core_co.v:196` 의 트리거 조건은 `taps_eff[0] && !taps_sampled_0_history` 이고
`taps_eff[0] = ~hit` 이므로, **hit 의 하강 에지마다 딱 한 번 측정**한다.

| | 값 |
|---|---|
| 스코프가 본 비트 주파수 | 34 ~ 86 kHz (평균 67.5 kHz) |
| ILA 가 본 히트 간격 (중앙값) | **15.95 µs → 62.7 kHz** |
| ILA 가 본 히트 간격 (스텝 안 평균) | **17.03 µs → 58.7 kHz** |

비트 주파수가 chirp 때문에 34~86 kHz 사이를 오가므로 그 평균과 잘 맞는다.
**LVDS → IBUFDS → CYINIT 경로는 살아 있다.**

> **★ 지금은 영교차의 절반만 찍고 있다.** 비교기는 주기당 2번(상승·하강 영교차) 반전하는데
> 코어는 **하강 에지에서만** 트리거한다. 양쪽 에지를 다 쓰면 위상 표본이 **2배**가 된다.
> FMCW 리샘플링(k-clock) 용도로는 의미 있는 차이다. → 제3부 참조.

### Mode 2 가 위상 시프트 클럭을 잘못 쓰고 있지는 않다

`OPERATION_MODE == 2` 는 `clk_200_fixed` 를 써야 한다 (`RTL/tdc_test_top.v:234`).
확인 방법: 위상 스텝 번호와 측정값이 무관해야 한다.

| 검사 | 값 | 시프트 클럭을 썼다면 |
|---|---|---|
| corr(loop_cnt, fine) | **−0.033** | ±1 에 가까움 |
| 스텝별 fine 평균의 표준편차 | **405 ps** | ~1443 ps (5000 ps 를 균일하게 훑으므로) |

→ **배선은 맞다.**

### 기타

- 다이 온도 **39.24 ~ 40.97 °C** (`T = raw × 503.975 / 65536 − 273.15`, raw 40622~40848)
- **DNA = 0x3D996854** ← 집 Zybo(0x641A285C)·회사 Zybo(0x2E496854) 와 다른 **새 칩**. 맞다.

## 4. ★ 9.75 ms 짜리 구멍의 정체 — 히트가 빠진 게 아니라 "기록을 안 한" 것

### 무엇이 보였나

ILA 로 받은 2,047개의 히트 간격 중 **127개가 9.73 ~ 9.76 ms** 였다. 나머지는 12~50 µs 인데
이것만 유독 **600배쯤 크다.**

### 원인

구멍이 나타나는 위치가 결정적이었다. **행 번호 15, 31, 47, 63, 79, … 정확히 16행마다**이고,
그 자리는 `current_loop_cnt_stable`(위상 스텝 번호)이 바뀌는 자리와 **완전히 일치**한다.

원인은 `RTL/tdc_test_top.v:464` 의 이 한 줄이다.

```verilog
localparam [4:0] CAP_PER_STEP = 5'd16;   // 스텝당 저장할 히트 수
```

### 쉽게 말하면 — 사진 촬영 비유

위상 시프터는 **한 스텝에 10 ms 씩 머물면서 280장을 찍는 카메라**다.
그 10 ms 동안 영교차는 계속 들어온다 — 17 µs 마다 하나씩이니 **한 스텝에 약 590발**이 지나간다.

그런데 ILA 에 저장하도록 허락된 것은 **스텝이 바뀐 직후 16발뿐**이다.
16발 담는 데 255 µs 가 걸리고, **남은 9.745 ms 동안은 히트가 들어와도 그냥 흘려보낸다.**
그러니 CSV 에서 이웃한 두 줄의 시각 차이가 9.745 ms 로 벌어진다.

> **히트가 유실된 게 아니라, 애초에 기록하지 않기로 되어 있는 구간이다.**

### 검산 (실측만으로 딱 맞는다)

`mode2.csv` 를 스텝 번호로 묶어서 계산했다.

| 항목 | 계산 방법 | 값 |
|---|---|---|
| 스텝당 저장된 히트 수 | 스텝별 행 개수 | **정확히 16발** (최소=최대=16) |
| 16발 담는 데 걸린 시간 | 스텝 안 (마지막 − 첫) 타임스탬프 평균 | **255.4 µs** |
| 스텝 체류 시간 | 스텝 첫 히트 → 다음 스텝 첫 히트, 평균 | **10000.2 µs** = 정확히 10 ms |
| **예상 구멍** | 10000.2 − 255.4 | **9744.7 µs** |
| **실측 구멍** | 16번째 히트 → 다음 스텝 첫 히트, 평균 | **9744.7 µs** |
| 차이 | — | **0.0 µs (0.00 %)** |

**완전히 일치한다. 하드웨어 이상이 아니다.**

### 그래서 이 데이터를 얼마나 믿을 수 있나

- 한 스텝에 지나간 영교차 590발 중 16발만 저장 → **전체의 약 2.7 % 만 본 것**이다.
  (128스텝 × 590발 ≈ 75,100발 중 2,048발)
- **탭 분포를 보는 데는 치우침이 없다.** 스텝이 바뀌는 시점과 비트 신호는 서로 무관하므로
  "스텝 바뀐 직후 16발"이라는 조건이 측정값을 특정 탭으로 몰지 않는다
  (corr(loop_cnt, fine) = −0.033 으로 확인).
- **다만 FMCW 신호로서는 못 쓴다.** 255 µs 만 보고 9.7 ms 를 건너뛰므로 위상이 끊긴다.
  chirp 주기가 495 µs 이니 **한 chirp 의 절반만 보고 20 chirp 을 건너뛰는 셈**이다.
  → 실제 FMCW 측정을 하려면 이 게이팅을 반드시 꺼야 한다.

### 왜 Mode 2 인데 위상 스텝이 도나

`CAP_PER_STEP` 게이팅도, 위상 시프터 자체도 **모드와 무관하게 항상 돈다.**
스텝당 16발은 **Mode 0(위상 스윕)에만 필요한 장치**다 — 스텝마다 여러 발을 평균 내어
측정 잡음을 √16 = 4배 줄이려고 2026-08-20 에 넣은 것이다.
Mode 1·2 에는 위상 스텝이라는 개념 자체가 없으므로 이 게이팅이 걸릴 이유가 없다.
→ **`dps_en` 레지스터로 끄는 것이 맞다** (제3부 참조).

## 5. ROM 은 `dummy_rom.coe` 였다 — 의도된 무교정 측정

> **먼저 밝혀둘 것**: 이번 측정은 **일부러 교정 없이** 돌린 것이다. 비트 주파수가 34~86 kHz 로
> 높지 않아, 먼저 신호가 제대로 들어오는지부터 보려고 선형 램프(`dummy_rom.coe`)를 그대로 둔 채
> 쟀다. **실수가 아니다.** 아래는 "그래서 이 데이터의 fine 값을 어떻게 읽어야 하는가" 를 정리한 것이고,
> 다음 교정 작업(제2부)에서 무엇을 조심해야 하는지의 근거이기도 하다.

### 어떻게 확인했나

타임스탬프 계산식은 `timestamp_ps = coarse × 5000 − ROM[탭번호]` 이므로, 거꾸로

```
ROM 값 = 5000 − (timestamp_ps mod 5000)
```

로 **ROM 이 실제로 돌려준 값**을 뽑을 수 있다. 2,048발에서 나온 값은 250종이었고,
값들의 간격이 전부 **17 아니면 18 ps** 였다 (= 5000/280 = 17.857).

저장소의 COE 4개와 대조한 결과 **2,048발 전부가 `python/dummy_rom.coe` 로 재현**됐다 (불일치 0발).

```
dummy_rom.coe : 320줄, 간격 17 ps(46개) / 18 ps(273개)
                v[0]=0   v[279]=4982   v[280]=5000   v[319]=5696
```

### 이 표가 이 보드에 안 맞는 이유 — 자(尺) 비유

TDC 는 **눈금 320개짜리 자**다. ROM 은 "눈금 하나 = 몇 ps 인가"를 적어 둔 환산표다.

`dummy_rom.coe` 에는 **"280칸이 5 ns 를 덮는다"**(= 눈금 하나 17.857 ps)고 적혀 있다.
그런데 이 보드는 **320칸을 다 쓴다.** 실제 눈금은 5000/320 = **15.6 ps 이하**다.

→ 자를 **14.3 % 부풀려 읽고 있었다.** 오차는 뒤로 갈수록 쌓인다:

```
오차(탭 t) = t × (15.625 − 17.857) = −2.23 ps × t
             탭 100 → −223 ps      탭 279 → −623 ps      탭 319 → −712 ps
```

*(도출값. 15.625 ps 는 "320칸이 정확히 5 ns 를 덮는다"는 가정에서 나온 것으로 아직 측정값이 아니다.)*

### 눈에 보이는 증상 — 접힘(folding)

`dummy_rom.coe` 는 **탭 280부터 값이 5000 ps 를 넘는다** (5000 → 5696).
`timestamp = coarse×5000 − ROM` 에서 5000 을 넘으면 coarse 에서 빌려오므로,
**탭 280~319 가 탭 0~39 와 똑같은 값**으로 찍힌다.

| | 값 |
|---|---|
| 두 탭에 동시 대응하는 fine 값 | 250종 중 **37종** (예: fine=0 → 탭 {0, 280}) |
| 겹침 자리에 떨어진 히트 | **559발 (27.3 %)** |
| 겹침 없는 구간(탭 40~279)의 밀도 | 1,489발 ÷ 240탭 = 6.20발/탭 |
| 그 밀도로 80탭을 채우면 | 496발 |
| **예측 대비 실측** | **1.13배** — 겹침 가설이 맞다 |

**히스토그램에서 앞머리 40칸만 2배로 솟아 보이는 것은, 실제로 넓어서가 아니라
뒤쪽 40칸이 거기 포개져 있기 때문이다.**

## 9. 작업 ① — 슬라이스 열 높이 확인 (5분, 합성 불필요)

Vivado 에서 아무 프로젝트나 열고 (또는 `link_design -part xc7z020clg484-1`) Tcl Console 에 그대로 붙여넣는다.

```tcl
foreach col {42 43} {
  set ys {}
  foreach s [get_sites SLICE_X${col}Y*] { regexp {Y(\d+)$} $s -> y; lappend ys $y }
  set ys [lsort -integer $ys]
  set gap "연속"
  for {set i 1} {$i<[llength $ys]} {incr i} {
    if {[lindex $ys $i] != [lindex $ys [expr $i-1]]+1} { set gap "끊김 @Y[lindex $ys [expr $i-1]]"; break }
  }
  puts "SLICE_X$col : Y0 ~ Y[lindex $ys end] ($gap), 타입 [get_property SITE_TYPE [get_sites SLICE_X${col}Y0]]"
}
```

**적어올 것**: 출력 두 줄 그대로.

| 결과 | 다음 설계 |
|---|---|
| Y111 이상 연속 | **448탭 (112단)** |
| Y95 ~ Y110 | **384탭 (96단)** |
| Y95 미만 | 재검토 |

> **왜 448 이 상한인가.** CARRY4 체인은 한 열 안에서 수직으로만 이어지므로 **열 높이가 곧 상한**이다.
> 그리고 RTL 쪽 상한이 하나 더 있다: `sum_fine`·`ts_fine_idx` 가 `[8:0]`(≤511), 히스토그램이 512칸,
> `stg3_group` 이 `[7:0]`. **448 = 4×7×16 이면 선언 폭을 하나도 안 고쳐도 된다.**
> 512 로 가면 `sum_fine` 이 10비트가 되어 fine 인덱스·히스토그램 주소·ROM 주소가 전부 따라 넓어진다.

## 11. 작업 ③ — Mode 0 + linear COE 전달함수 (Q1 확정)

**빌드 B (`OPERATION_MODE = 0`, ROM = `tdc_calib_linear_rom.coe`)**. ILA 설정은 기존 지시서 §5-3 그대로.
→ `before_tf_1.csv` ~ `_3.csv` (스텝당 16발 × 280스텝 = 4,480행)

> **★ 반드시 `tdc_calib_linear_rom.coe` 를 쓸 것.** 이 파일은 최댓값이 4992 라 **5000 을 넘지 않는다.**
> 즉 오늘 `dummy_rom.coe`(v[319]=5696)에서 생긴 **탭 0~39 ↔ 280~319 접힘이 없다.**
> 읽은 값이 곧 탭 번호다. `dummy_rom.coe` 로 이 측정을 하면 오늘과 똑같은 3중 모호에 다시 걸린다.

### 그리는 법

가로축 `current_loop_cnt_stable` 1~280 (한 칸 = 17.857 ps 의 실제 시간),
세로축 `fine = 5000 − (final_timestamp_ps mod 5000)` [ps].
같은 스텝의 16발은 평균 내면 된다.

### 판정 — 그래프 모양만 보면 갈린다

| 모양 | 뜻 | `VALID_TAP_HI` | 사각지대 |
|---|---|---|---|
| 단조 상승 → 최대 M(<319) 도달 후 랩 | **(가)** 체인 > 5 ns (Zybo 형) | M | 없음 |
| 단조 상승 → 319 근처 도달 후 랩, **평평한 구간 없음** | **(나)** 체인 ≈ 5 ns | **319** | 없음 |
| 상승하다 **0 근처로 뚝 떨어져 K스텝 평평** 후 랩 | **(다) 포화** | 319 | **K × 17.857 ps** |

**(다) 에서 왜 0 으로 떨어지나**: §7 에 쓴 대로 `sum_fine = 320` 이면 ROM 주소가 범위 밖이라
0 을 돌려주고, 그 결과 fine 이 탭 0 의 값으로 보인다. **스윕 한가운데에서 갑자기 0 이 되어
여러 스텝 유지되면 그게 포화다.**

**적어올 것**: 최대 fine 값, 그때의 탭 번호, 평평한 구간이 있으면 스텝 수 K.

### (다) 가 나오면 파이썬도 고쳐야 한다 (집에서)

`Making_COE_Mode_0.py` 는 **유효 구간이 정확히 5000 ps 를 덮는다고 가정**한다
(`lut_valid = T_PERIOD_PS / H × (...)`). 사각지대가 있으면 320칸이 실제로 덮는 시간은
`5000 − K × 17.857` ps 이므로, 그대로 돌리면 표가 `5000 / (5000 − K×17.857)` 배로 늘어난다.
**집 보드에서 겪은 것과 같은 종류의 오차가 반대 방향으로 생긴다.**
→ `T_PERIOD_PS` 를 상수가 아니라 매크로로 빼는 수정이 필요하다.
