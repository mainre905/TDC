## 1. 무엇을 어떻게 했나

세 단계이고, **두 보드에 완전히 같은 코드를 적용**했습니다.

```
① Mode 1 (링오실레이터)  →  히스토그램 3회 → 유효탭 결정 → 코드밀도 LUT 생성
                              ro_cal / ro_val1 / ro_val2
                                   ↓
② Mode 1 cal/val         →  ro_cal 로 만든 LUT 을 ro_val1·ro_val2 로 평가
                              (교정 품질. 이것이 설계 의도)
                                   ↓
③ Mode 0 (MMCM 위상 스윕) →  참 시간축 대비 전달함수 측정
                              BEFORE(등간격 ROM) vs AFTER(코드밀도 LUT)
```

### 왜 이 구조인가

- **Mode 1** 은 링오실레이터가 클럭과 무관하게 히트를 뿌립니다. 히트가 한 탭에 떨어질 확률이 그 탭의 폭에 비례하므로, **히트 수를 세면 폭을 알 수 있습니다**(코드밀도법). 참 시간을 몰라도 됩니다.
- **Mode 0** 은 MMCM 위상을 17.857 ps씩 280번 옮깁니다. 이 위상값이 **참 시간**이므로, 보고된 시각과 비교해 정확도를 직접 잴 수 있습니다.
- **Mode 2**(실제 측정)는 Mode 1 과 **같은 클럭 `clk_200_fixed`** 를 씁니다 (`RTL/tdc_test_top.v:224-236`). Mode 0 만 `clk_200_shifted` 입니다.

### 각 캡처가 어느 빌드에서 나왔나

| 빌드 | `OPERATION_MODE` | ROM | 산출 파일 |

## 2. Mode 1 교정 — 지연선은 눈금이 균일하지 않다

![탭 폭](fig/2026-08-23_bin_widths.png)

TDC 는 320개 탭이 새겨진 자입니다. **이상적이라면 모든 탭 폭이 같아야 하지만 실제로는 0.7 ps 부터 84.9 ps 까지 흩어져 있습니다.**

| | 집 보드 | 회사 보드 |
|---|---|---|
| 유효탭 (평균의 5 % 미만 트리밍) | **2 ~ 299 (298개)** | **2 ~ 283 (282개)** |
| 3캡처 일치 | 2~299 / 2~299 / 2~299 ✔ | 2~283 / 2~283 / 2~283 ✔ |
| 총히트 (cal) | 80,917,853 | 330,354,107 |
| **LSB** = 5000/N | **16.779 ps** | **17.730 ps** |
| 탭 폭 최소 / 중앙 / 최대 | 0.70 / 14.82 / **84.90** ps | 0.28 / 16.88 / **63.46** ps |
| 폭 표준편차 | 11.08 ps | 12.37 ps |
| 등가 bin 폭 `w_eq` | 27.09 ps | 28.42 ps |
| **양자화 한계 σ** | **7.82 ps** | **8.20 ps** |
| (폭이 균일했다면 LSB/√12) | 4.84 ps | 5.12 ps |

**집 보드 지연선이 더 빠릅니다** — 같은 5 ns 안에 298개 탭이 들어갑니다(회사 282개). 그만큼 LSB 가 작고 양자화 바닥도 낮습니다.

### 양자화 한계란 무엇인가

TDC 가 보고하는 건 **탭 번호**입니다. 그 탭 안 어디에 히트가 떨어졌든 보고값은 같습니다. 교정표가 아무리 정확해도 탭 안쪽 위치는 알 수 없고, 그 모르는 부분이 오차로 남습니다. **교정으로 절대 못 줄이는 바닥**입니다.

폭 `w` 인 탭 하나에서 오차는 `[−w/2, +w/2]` 균일분포 → 분산 `w²/12`. 히트가 탭 `i` 에 떨어질 확률은 `p_i = w_i/Σw` 이므로

```
σ² = Σ p_i · (w_i²/12) = Σ w_i³ / (12 · Σ w_i)      →   σ = w_eq/√12,  w_eq = √(Σw³/Σw)
```

모든 폭이 같으면 `σ = LSB/√12` 로 교과서 결과와 일치합니다. 이 식은 **Won & Lee, IEEE TIM 2016, 식 (4)** 와 동일합니다.

**`w³` 가중이라 넓은 탭이 세제곱으로 기여합니다.** 집 보드에서 `Σw³` 기여 상위:

| 탭 | 폭 | `Σw³` 대비 |
|---|---|---|
| 100 | 84.90 ps | **16.7 %** |
| 32 | 44.44 ps | 2.4 % |
| 3 | 44.17 ps | 2.3 % |
| (중앙값 탭) | 14.82 ps | 0.09 % |

다만 **한두 개 탭 문제가 아닙니다.** 가장 넓은 탭 1개를 중앙값 폭으로 쪼개도 σ 는 7.82 → 7.19 ps 로 8 %만 줄고, 넓은 10개를 다 쪼개야 6.68 ps 입니다. 폭 분포 전체가 퍼져 있는 것이 원인입니다.

### 발견 — 두 보드 모두 탭 100 이 가장 넓다

| 보드 | 탭 100 폭 (ro_cal / ro_val1 / ro_val2) | 평균 대비 |
|---|---|---|
| 집 | 84.90 / 85.01 / 84.69 ps | 5.1배 |
| 회사 | 63.46 / 62.80 / 62.74 ps | 3.6배 |

**서로 다른 칩인데 같은 탭 번호**이고 3회 캡처 모두 재현됩니다. 실리콘 편차가 아니라 **배치 구조에서 오는 것**입니다. 탭 100 = CARRY4 스테이지 25 의 0번 출력입니다.
→ **구체적 원인(어느 라우팅 자원, 어느 경계)은 넷리스트로 확인하지 않았습니다. 가설 단계입니다.**

## 3. Mode 1 cal/val — 교정 품질 (설계 의도)

![Mode1 cal/val](fig/2026-08-23_mode1_calval.png)

`ro_cal` 로 LUT 을 만들고, **그 LUT 을 만드는 데 쓰지 않은** `ro_val1` / `ro_val2` 로 평가했습니다.

| 보드 | 검증 캡처 | | DNL max | DNL rms | INL max | INL rms |
|---|---|---|---|---|---|---|
| **집** | ro_val1 | 무교정 | 4.07 | 0.66 | 63.0 ps | 20.8 ps |
| | | **교정** | **0.05** | **0.01** | **2.1 ps** | **1.1 ps** |
| | ro_val2 | 무교정 | 4.05 | 0.66 | 62.4 ps | 20.2 ps |
| | | **교정** | **0.06** | **0.01** | **3.4 ps** | **1.9 ps** |
| **회사** | ro_val1 | 무교정 | 2.54 | 0.70 | 52.8 ps | 19.7 ps |
| | | **교정** | **0.07** | **0.02** | **4.7 ps** | **2.1 ps** |
| | ro_val2 | 무교정 | 2.54 | 0.70 | 53.8 ps | 19.5 ps |
| | | **교정** | **0.05** | **0.01** | **3.3 ps** | **1.4 ps** |

- **DNL** = (독립 캡처가 말하는 실제 폭 − 교정표가 배정한 폭) / LSB. 넓은 탭이 +, 빈 탭이 −1.
- **INL** = 두 누적 시간축의 차, 평균 제거 [ps].

**두 보드가 사실상 동일합니다.** 교정 자체는 어느 보드에서나 같은 수준으로 작동합니다.

> **이 숫자의 한계**: 두 히스토그램을 서로 비교한 값이라 **cal 과 val 이 공유하는 편향은 상쇄되어 보이지 않습니다.** 1~2 ps 는 링오실레이터 히스토그램의 **재현성 바닥**이지 참 시간 대비 절대 정확도가 아닙니다.

## 4. Mode 0 검증 — 참 시간 대비 오차

![Mode0 INL](fig/2026-08-23_mode0_inl.png)

MMCM 위상을 280스텝(17.857 ps씩) 옮기며 전달함수를 측정하고, 직선을 적합해 잔차(=INL)를 봤습니다. 랩(클럭 경계) 스텝은 그 근처 ±5스텝과 함께 제외했습니다 — 그 스텝은 16샘플이 경계 양쪽으로 갈라져 평균이 무의미하기 때문입니다.

| 보드 | | 점수 | 기울기 | 이득오차 | INL p-p | **INL rms** | 경계 불연속 | 경계제거 p-p | 경계제거 rms |
|---|---|---|---|---|---|---|---|---|---|
| **집** | BEFORE | 270 | 1.0005 | 0.05 % | 81.4 ps | **15.67 ps** | +11.3 ps | 79.9 | 14.36 |
| | AFTER | 270 | 1.0031 | 0.31 % | 98.1 ps | **25.96 ps** | **+35.3 ps** | 79.7 | 17.14 |
| **회사** | BEFORE | 270 | 0.9927 | 0.73 % | 112.6 ps | **18.76 ps** | −8.6 ps | 109.3 | 18.11 |
| | AFTER | 270 | 1.0011 | 0.11 % | **78.1 ps** | **15.71 ps** | +16.1 ps | **67.0** | **12.75** |

**그림 3 에서 눈으로 보이는 것**: 집 보드 AFTER(파란선)가 클럭 경계(점선)에서 −30 ps 에서 +40 ps 로 **통째로 뛰어오릅니다.** 이것이 경계 불연속 +35.3 ps 입니다.

### 경계 불연속이란

스윕은 클럭 한 주기를 훑으며 경계를 정확히 한 번 넘습니다. 하드웨어는 `timestamp_ps = ts_coarse × 5000 − calibrated_fine_ps[fine_idx]` 로, **조대 카운터가 주기당 정확히 5,000 ps 를 기여**합니다. 그러니 경계 앞뒤 잔차가 어긋나 있다면 그건 **ROM 풀스케일이 5,000 ps 가 아니라는 뜻**입니다.

두 보드 공통으로 **AFTER 의 경계 불연속이 BEFORE 보다 큽니다** (집 +11.3 → +35.3, 회사 −8.6 → +16.1). 코드밀도 LUT 은 두 칩 모두에서 경계에 +25 ps 안팎의 점프를 새로 만듭니다. 방향과 크기가 일치하므로 우연이 아닙니다.

> **정의에 따라 값이 달라집니다.** 위 표는 전역 정의(전체를 한 직선에 적합한 뒤 두 갈래 잔차 평균의 차)입니다. 국소 정의(경계 양쪽에서 각각 외삽해 그 차)로는 집 AFTER 가 +65.5 ~ +82.5 ps (창 폭 5~15 스텝 쓸기), BEFORE 가 +1.8 ~ +37.7 ps 로 불안정합니다. **어느 정의로도 AFTER 가 BEFORE 보다 크다**는 결론은 같습니다.

## 6. 이 비교를 왜곡하는 조건 차이 — 반드시 읽을 것

### (가) BEFORE 에 넣은 ROM 이 다릅니다

| | BEFORE ROM | 눈금 | 그 보드의 LSB | 이득 오차 |
|---|---|---|---|---|
| 집 | `tdc_calib_linear_rom.coe` | 16.779 ps/탭 | 16.779 ps | **0.05 %** |
| 회사 | `dummy_rom.coe` | 17.857 ps/탭 | 17.730 ps | **0.73 %** |

회사의 BEFORE 는 눈금이 그 보드에 맞지 않는 임의의 램프였고, 집의 BEFORE 는 이미 정확히 맞춰져 있었습니다.
**회사의 "개선" 중 상당 부분이 이 이득 오차를 LUT 이 바로잡은 몫입니다** — 기울기가 0.9927 → 1.0011 로 움직인 것이 그 증거입니다. 집은 고칠 이득 오차가 애초에 없었고(1.0005), 오히려 AFTER 에서 0.31 %로 나빠졌습니다.

### (나) 스텝당 샘플 수가 다릅니다

집 K=16, 회사 K=1. 스텝 평균의 측정 잡음이 집은 약 1.3 ps, 회사는 약 4.5 ps 로 **회사가 3~4배 큽니다.**
잡음을 빼면 회사 BEFORE 18.11 → 약 17.5, AFTER 12.75 → 약 11.9 ps 입니다. 결론의 방향은 바뀌지 않습니다.

### 공정한 비교를 하려면

**회사 보드에서 (a) 이득 정합된 선형 COE 를 BEFORE 로 쓰고 (b) K=16 으로 재측정**해야 합니다. 온도 챔버가 필요 없는 상온 측정이므로 다음 출근 때 가능합니다.

## 7. 문헌 대조 — 우리 방법이 표준인가

`paper/ref/` 33편 중 30편을 텍스트 추출해 검증 방법론을 조사했습니다.

### 표준 검증은 2단 구조

**1단 — 코드밀도 DNL/INL**: 클럭과 무관한 랜덤 히트를 외부 함수발생기로 넣고 히스토그램. 샘플 수는 90,900(Cross-Detection), 102,400(Won & Lee) 수준. **우리 `DNL_INL_codedensity.py` 와 같습니다.**

**2단 — 참 시간 기준**: 두 가지가 쓰입니다.

| 방법 | 내용 | 대표 논문 |
|---|---|---|
| **케이블 지연법** | 발생기 출력을 T커넥터로 나눠 길이가 다른 동축 케이블 2개로 두 채널에 입력. 차이를 수만 번 재서 σ. 단일채널 = RMS/√2 | Cross-Detection (케이블 8/30.3/50.2 cm), *Low Temperature Coefficient TDC* — "The cable delay method is usually used to measure the RMS precision" |
| **발생기 지연 스윕법** | 트리거 지연을 미세하게 쓸며 각 지연마다 N회 측정. 평균과 참값의 차 = 정확도, 표준편차 = single-shot precision | **Korkan & Yuksel (TIM 2026)** — AFG3101C, 10 ps 스텝 490 ps 까지, 스텝당 1,024회. **Tontini & Gasparini (TIM 2018)** — Keysight 81150A, **1 ps 스텝**, 스텝당 8,192회 |

**★ 우리 Mode 0 는 지연 스윕법의 온칩 버전입니다.** 참 시간을 외부 발생기가 주느냐 MMCM 이 주느냐만 다릅니다. Zybo 에 50 Ω 입력이 없어 케이블 지연법을 못 쓰는 것을 이 방식이 대체합니다.

### 우리가 겪은 문제를 그대로 다룬 논문

**Tontini & Gasparini, "Design and Characterization of a Low-Cost FPGA-Based TDC," IEEE TIM 2018** 이 우리와 같은 대조 실험을 했습니다:

> "we present a novel comparison between the DNLs obtained with two different methods: **statistical code density test** and **using a finely controlled delay source**."

결론:

> "the DNL obtained through the code density test closely matches the DNL obtained through the instrument delay sweep method. This is a proof of the reliability of the statistical code density test. **Outliers (smallest and highest values) are not considered, due to the delay wrapping around the clock edge that produces both the highest and lowest values, thus distorting the median statistic.**"

**클럭 에지 랩에서 끝단 코드를 배제하는 것이 표준 관행**입니다. 우리가 랩 ±5스텝을 제외한 것은 임의 조작이 아닙니다.

### 코드밀도가 아닌 방법

| 방법 | 원리 | 성능 예 |
|---|---|---|
| 변환곡선 직접 측정 | 지연 스윕으로 코드 전이점을 직접 재서 `DNL_i = ((T_{i+1}−T_i)−LSB)/LSB` | Tontini TIM 2018 |
| **DPS 자체를 TDC 로** | 지연선 없이 MMCM 위상 시프트 반복 측정 | Korkan & Yuksel TIM 2026 — 18 ps 해상도, 11~16 ps single-shot, LUT 3.97 % |
| Wave Union | 한 히트에 여러 전이를 실어 다중 측정 후 평균 | Wu (Fermilab) |
| Multi-chain cross segmentation | 병렬 캐리체인을 엇갈려 샘플링해 등가 체인 생성 | Sensors 2022 — **1.3 ps 해상도, 4.6 ps single-shot, 0.0002 ps/°C** |
| Tuned delay line | CARRY4 의 O/CO 출력을 섞어 missing bin 제거 | Won & Lee TIM 2016 — DNL σ 0.90 → 0.50 LSB |
| Bin decimation / Online dual-chain / Vernier / 온도 자동보정 | — | — |

**중요**: 위 대부분은 교정법이 아니라 **구조 개선**(초광폭 bin 을 애초에 안 만드는 방법)입니다. 리뷰 논문(*A Review of Advancements and Trends in TDCs Based on FPGA*):

> "as long as ultrawide bins exist, even when multiple TDLs are used, the measurement precision will not significantly improve because the ultrawide bins still dominate"

우리 `Making_COE_Mode_0.py` 의 **반폭 누적 공식**도 문헌 그대로입니다 (*A Low-Resources TDC for Multi-Channel Direct ToF Readout*): "Half of the first bin width corresponds to the delay mapped to the number '1'…"

## 9. 미결 — 설명하지 못한 관찰

Mode 1 과 Mode 0 의 히스토그램이 지연선 끝을 다르게 봅니다.

| 탭 | Mode 1 (`ro_cal`, 8,092만 발) | Mode 0 (`mode0_hist_1`, 2억 2,400만 발) |
|---|---|---|
| 295 | 286,161 (1.06× 평균) | 558,495 (0.73×) |
| 296 | 409,049 (1.51×) | 70,874 (0.11×) |
| **297** | **513,527 (1.90×)** | **1 발** |
| 298 | 84,274 (0.31×) | 0 |
| 299 | 118,682 (0.44×) | 0 |

**Mode 1 은 탭 297 을 그 구간에서 가장 큰 bin 으로 보고, Mode 0 은 존재하지 않는 것으로 봅니다.** 같은 칩, 같은 온도(42.2 °C)입니다. Mode 0 이 못 가는 탭 297~299 에 LUT 이 배정한 폭은 **44.3 ps (클럭 주기의 0.89 %)** 이고, 이것이 눈금을 압축해 경계 점프를 만듭니다.

**히트수 임계값으로는 잡을 수 없습니다** — 탭 297 은 평균의 1.90배로, 그 구간에서 가장 큰 bin 입니다.

### 가설 (검증 안 됨)

Mode 1 은 `clk_200_fixed`, Mode 0 은 `clk_200_shifted` 를 씁니다. 두 클럭의 지터/듀티 차이로 지연선이 한 주기에 훑는 탭 수가 달라질 수 있습니다.
→ **RTL·넷리스트·타이밍 모델로 확인한 바 없습니다. 가설입니다.**

한편 링오실레이터는 `tdc_test_top.v:94` 의 `ro_enable_reg <= clk_locked` 때문에 **모드와 무관하게 항상 돕니다.** 따라서 "링오실레이터 전력/잡음이 다이 조건을 바꾼다"는 설명은 기각됩니다 — 두 모드 다 켜져 있습니다.

### 이 가설을 가르는 측정

Build 1(Mode 1)과 Build 2(Mode 0)는 **비트스트림이 다릅니다.** 그래서 차이가 (a) 모드/클럭 때문인지 (b) 빌드가 달라서인지 구분되지 않습니다.
→ **같은 비트스트림에서 두 조건을 비교**해야 합니다.

## 부록 A. 용어

| 용어 | 뜻 |
|---|---|
| **탭 (tap)** | 지연선의 눈금 하나. 320개 중 실제로 쓰이는 것이 유효탭 |
| **LSB** | 평균 탭 폭 = 5000 ps / 유효탭 수 |
| **DNL** | (실제 폭 − 배정 폭) / LSB. 눈금 하나하나가 얼마나 어긋났나 |
| **INL** | 누적 시간축의 오차 [ps]. 보고된 시각이 참값에서 얼마나 벗어났나 |
| **등가 bin 폭 `w_eq`** | `√(Σw³/Σw)`. 폭이 들쭉날쭉한 자를 "모든 눈금이 이 폭인 자"로 환산한 값 |
| **양자화 한계 σ** | `w_eq/√12`. 교정으로 절대 못 줄이는 오차 바닥 |
| **경계 불연속** | 클럭 한 주기를 넘을 때 보고 시각이 튀는 양. 0 이어야 정상 |
| **cal/val 분리** | LUT 을 만든 데이터와 평가하는 데이터를 분리하는 것. 안 하면 자기 일관성만 잰다 |
