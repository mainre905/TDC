## 0. 이 실험이 답하려는 질문

> **RO 주파수로 CARRY4 탭 지연의 온도 드리프트를 보정할 수 있는가?**

로드맵 §2.2(RO 기반 실시간 스케일 보정)의 성립 여부가 여기서 갈린다.

**필요 조건:** RO(LUT + 일반 라우팅)와 딜레이라인(CARRY4 전용 캐리 MUX)이
**같은 방향·같은 비율**로 온도에 반응해야 한다. 서로 다른 실리콘 구조이므로
자동으로 보장되지 않는다.

| 결과 | 결론 |
|---|---|
| 두 상대변화가 **일치** | RO 프록시 성립 → §2.2 유효, 온라인 보정 설계로 진행 |
| **어긋남** | RO 프록시 실패 → Pan 2014처럼 **전용 캐리체인**을 센서로 써야 함 |

## 1. ⛔ 절대 지킬 것

### 1-1. 실험 중 재합성(re-synthesis) 금지

**같은 비트스트림으로 전 온도를 측정해야 한다.**

이유:
- 재빌드하면 배치·배선이 바뀌어 **INL 패턴이 달라진다** → 온도 간 비교(paired analysis)가 깨진다
- **CDC 결손 구간이 이동한다** (실측 확인: 133~206 → 73~156으로 이동)
- RO 주파수 절대값이 바뀐다 (실측: 63.45 → 64.69 MHz, 온도 효과의 15배)

**허용:** 같은 `.bit` 파일 재프로그래밍, Vivado 재시작, ILA 설정 변경
**금지:** Run Synthesis / Run Implementation / Generate Bitstream, RTL·XDC·COE 수정

### 1-2. COE 변경 금지

현재 ROM에 로드된 COE를 그대로 둔다. 우리는 절대 지연이 아니라 **온도 간 상대 변화**를
보므로, LUT가 상수로 유지되기만 하면 된다.

> 참고: 현재 IP는 `tdc_calibration_lut.coe`(루트, 2026-07-02 구버전)를 참조 중.
> 내용이 무엇이든 **바꾸지만 않으면** 실험은 성립한다.

## 2. 사전 준비 (오늘 밤 또는 출근 직후 1회)

### 2-1. Mode 0 빌드

```verilog
// RTL/tdc_test_top.v 9행
parameter integer OPERATION_MODE = 0    // 0 = DPS (현재 1이므로 변경 필요)
```

나머지(COE·XDC·ILA IP)는 **전부 그대로**.

- ILA IP는 **9프로브** 상태여야 함: `[1,1,9,48,9,32,32,1,16]`
- 빌드 후 **`.bit` 파일을 안전한 곳에 백업** (실수로 재빌드했을 때 복구용)

### 2-2. 빌드 직후 기준점 확보 (실온)

온도 조절기 켜기 전, **실온 상태에서 1회 측정**해 둔다. 이것이 $T_{ref}$가 된다.

## 3. 측정 항목 — 온도마다 2종류

같은 빌드에서 **ILA 설정만 바꿔** 두 번 캡처한다.

| | 캡처 A — RO 주파수 | 캡처 B — CARRY4 기울기 |
|---|---|---|
| 목적 | RO가 온도에 어떻게 변하나 | CARRY4 탭 지연이 어떻게 변하나 |
| 트리거/자격저장 | `probe7 (meas_strobe) == 1` | `probe0 (capture_trigger) == 1` |
| 조작 | **버튼 안 누름** (정지 상태) | `btn_shift` 1회 |
| 소요 | 약 10초 (자동 완료) | 약 3초 + 정지 버튼 |
| 결과 | 1024 샘플 | 200~250 샘플 |

> **왜 캡처 A를 정지 상태에서 하나:** Mode 0에서 ILA는 `clk_200_shifted`로 샘플하는데
> `meas_strobe`는 `clk_200_fixed` 도메인이다. 스윕이 끝나면 위상이 원점으로 돌아오고
> (280 × 17.857 ps = 5000 ps = 1주기), 그 위상은 안전 구간임이 확인됐다(스텝 1~72 정상).
> **스윕 중에는 캡처 A를 하지 말 것.**

## 4. ILA 설정 (Hardware Manager)

### 공통 (Settings 패널)
| 항목 | 값 |
|---|---|
| Trigger mode | `BASIC_ONLY` |
| **Capture mode** | **`BASIC`** ← 이걸 켜야 Capture Setup 탭이 생김 |
| Number of windows | 1 |
| Trigger position in window | **0** |

### 캡처 A — RO 주파수
```
Window data depth       : 1024
Trigger Setup           : probe7 (meas_strobe) == [B] 1
Capture Setup(자격저장)  : probe7 (meas_strobe) == [B] 1
```
→ Run(▶) 후 **약 10초 대기하면 자동 완료**

### 캡처 B — CARRY4 기울기
```
Window data depth       : 1024
Trigger Setup           : probe0 (capture_trigger) == [B] 1
Capture Setup(자격저장)  : probe0 (capture_trigger) == [B] 1
```
→ Run(▶) → `btn_shift` 1회 → 약 3초 → **카운트가 멈추면 정지 버튼(⏹)**

> 캡처 B는 CDC 결손 때문에 1024를 절대 못 채운다. 200~250에서 멈추는 게 **정상**이다.

### Export (공통)
```
File → Export → CSV,  Radix = UNSIGNED
```

## 6. 온도 지점별 절차

각 온도에서 아래를 순서대로:

1. **온도 설정** → **열평형 대기**
   - System Monitor 값이 **2분 이상 변하지 않을 때까지** 기다린다
   - 보통 10~15분. 급하게 하면 드리프트가 데이터를 오염시킨다

2. **온도 기록** (System Monitor 값, 소수점 2자리)

3. **캡처 A (RO)** — 버튼 누르지 말 것
   - Run → 10초 → 자동완료 → Export

4. **캡처 B (CARRY4)** — 3회 반복
   - Run → `btn_shift` → 정지 → Export
   - **3회 반복**해서 평균낸다 (정밀도 √3배 향상)

5. 다음 온도로

**소요 시간:** 온도당 약 20분 × 5지점 ≈ **1시간 40분**

## 9. ✅ 첫 온도에서 반드시 확인 (중요)

시간 낭비를 막기 위해 **1번 지점 측정 직후** 아래를 확인한다.

### 캡처 A (RO) 정상 판정
- 행 수 **1024**, 모든 행 `meas_strobe = 1`
- `ro_meas_cnt`가 **158,000~163,000 범위**에서 **샘플마다 조금씩 다름**
- 전부 같은 값이면 → 자격저장 미설정 의심
- 0 또는 터무니없는 값 → 프로브 연결 확인

### 캡처 B (CARRY4) 정상 판정
- 행 수 **200~250**, 모든 행 `capture_trigger = 1`
- `current_loop_cnt`가 **1~280 범위에 분포** (중간에 결손 구간 있는 게 정상)
- `final_timestamp_ps`가 **단조 증가**
- loop_cnt가 한 값만 나오면 → 자격저장 미설정 (스윕 후 상태를 캡처한 것)

**하나라도 이상하면 다음 온도로 넘어가지 말고 설정부터 바로잡을 것.**

## 10. 문제 발생 시

| 증상 | 대처 |
|---|---|
| 캡처 B가 1024를 안 채우고 멈춤 | **정상.** 정지 버튼으로 회수 |
| 캡처 B 행 수가 100 미만 | CDC 결손 구간이 넓어진 것. 그대로 기록하고 진행 |
| 보드 인식 안 됨 | 재프로그래밍(같은 `.bit`)은 **허용**. 재빌드는 금지 |
| Vivado 크래시 | 재시작 후 같은 `.bit` 다운로드. ILA 설정 다시 입력 |
| 온도가 목표에 안 닿음 | 도달 가능한 온도까지만. 지점 수보다 **평형이 중요** |
| 실수로 재합성함 | **그 시점부터 새 시리즈로 간주.** 기준점(실온)부터 다시 측정 |

## 11. 돌아와서 할 분석 (Claude가 수행)

CSV를 `python/`에 넣고 알려주면 아래를 산출한다.

### 11-1. CARRY4 스케일 — 짝지은 회귀
온도별로 독립 피팅하면 INL 때문에 정밀도가 2,630 ppm으로 나빠진다.
대신 **같은 loop_cnt끼리 직접 비교**해 INL을 공통모드로 상쇄시킨다.

```
각 스텝 s:   fine_T(s)  vs  fine_ref(s)   →  회귀 기울기 = 1/K(T)
K(T) = τ_tap(T) / τ_tap(T_ref)
```

### 11-2. RO 스케일
```
K_RO(T) = f_RO(T_ref) / f_RO(T)
```

### 11-3. 최종 판정
| 비교 | 의미 |
|---|---|
| $\Delta\tau_{carry}/\tau$ vs $\Delta f_{RO}/f$ | **두 구조가 같이 움직이는가** ← 핵심 |
| 각각의 ppm/°C | 온도계수 |
| 반전점(zero-TC) 위치 | RO는 60~65 °C. CARRY4는? |
| 상관계수 / 비례상수 | 프록시로 쓸 때의 보정 계수 |

## 12. 참고 — 이미 확보한 데이터

### RO 온도 특성 (2026-07-26, Mode 1 빌드)
| 온도 | 평균 주파수 | 구간 온도계수 |
|---|---|---|
| 38.5 °C | 64.687 MHz | |
| 47.8 °C | 64.733 MHz | +76.5 ppm/°C |
| 58.5 °C | 64.775 MHz | +60.6 ppm/°C |
| 67.2 °C | 64.771 MHz | **−7.1 ppm/°C** (반전) |

- 전체 45.2 ppm/°C, **온도 상승 시 빨라짐**(temperature inversion)
- 60~65 °C에서 계수가 0을 통과 → **RO 단독으로는 온도계로 부적합**
- 단기 변동 120 ppm (P-P 약 600 ppm)

> ⚠️ 이 데이터는 **Mode 1 빌드**에서 취득했다. 내일은 **Mode 0 빌드**이므로
> RO 절대 주파수가 다를 수 있다(빌드 간 15,000 ppm 차이 실측). 그래서 내일
> **캡처 A로 RO를 다시 측정**해 같은 빌드 내에서 비교한다.

### Mode 0 기준 측정 (2026-07-26, 40.48 °C)
```
기울기      1.027198 ps(측정)/ps(참)
잔차        std 64 ps,  P-P 322 ps   (INL이 지배)
유효 스텝   212 / 280
결손 구간   73 ~ 156
```
> 이 값도 **오늘 빌드** 기준이다. 내일 Mode 0로 재빌드하면 달라지므로
> **내일의 실온 측정을 새 기준점으로 삼는다.**

## 13. 알려진 버그 (실험에 영향 없음)

**Mode 0 `capture_arm` CDC 결손** — `current_loop_cnt`(9비트)를 동기화 없이
`clk_200_shifted`로 샘플해서, 특정 위상 구간의 스텝이 통째로 누락된다.

- 결손 폭 약 60~70 스텝(≈1,100~1,200 ps), 위치는 빌드마다 이동
- **같은 빌드 안에서는 고정**이므로 온도 간 비교에 영향 없음
- 수정은 **실험 종료 후**에 할 것 (재빌드하면 데이터 비교가 깨짐)
