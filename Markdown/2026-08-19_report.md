## 1. 빌드 재현성 — plain CO 빌드는 재현된다

각 ILA export에서 `(probe_read_addr_d1, histo_read_data)` 쌍의 주소별 최댓값으로 320탭 배열을

**유효 탭** = `h[i] > 0` 인 탭 수. **LSB** = 5000 / 유효탭수.

## 2. thermometer 재현성 — 재현되지 않았다

### 2-1. 실험

`RTL/tdc_fmcw_core_co_thermo.v`(= `tdc_fmcw_core_co.v` + `dbg_thermo[47:0]`/`dbg_valid` 2포트)를
top에 물리고 ILA `probe0`/`probe3`를 임시로 재배선해 빌드, Mode 1(RO)에서 1024샘플 캡처.
**측정 후 `git checkout HEAD -- RTL/tdc_test_top.v`로 원복 완료.**

`dbg_thermo[m] = taps_eff[64+m]` → 탭 64~111 (CARRY4 12단). 비트 `m mod 4` = CARRY4 내 위치.

### 2-2. 판정 기준 — 사슬(chain)

hit이 비동기라 클럭 대비 도착 시각이 균일하게 훑는다. 탭 *j*가 1로 읽힐 조건은
`θⱼ = (클럭 샘플 시각) − (파면이 탭 j를 지난 시각) > 0`.
**θⱼ가 고정이면** hit 시각이 커질수록 θ가 큰 탭부터 차례로 켜지므로, 한 CARRY4에서 관측 가능한
부분 패턴은 **정확히 3개이고 포함관계로 중첩**된다: {a} ⊂ {a,b} ⊂ {a,b,c}. 이를 **사슬**이라 한다.

> **사슬이면 = 전파 순서가 존재. 사슬이 아니면 = 전파 순서로 설명 불가.**

### 2-3. 결과 (측정)

| 캡처 | 사슬 성립 스테이지 | 패턴 종류 |
|---|---|---|
| **8/9 (`thermo_1csv.ila.csv`)** | **12 / 12** | **3** |
| BACK 8/13 (원복 XDC) | **0 / 12** | 7 |
| t1 8/13 (수정 XDC) | 0 / 12 | 7 |
| t2 8/13 (원복 XDC) | 0 / 12 | 7 |
| MIX 8/12 | 0 / 12 | 8 |

8/9은 12단 전부 사슬이고 10/12가 같은 순서 `CO[1]→CO[3]→CO[2]→CO[0]`, 나머지 2단은
CO[2]/CO[3]만 자리바꿈.

8/13은 한 스테이지 안에서 `0011`(40 %)과 `0100`(37 %)이 공존한다 — **서로를 부정하는 패턴**이라
어떤 고정 순서로도 설명되지 않는다.

**패턴 분포 총변동거리 TVD = ½Σ|p−q|**

```
BACK ↔ t1   0.036      BACK ↔ 8/9   0.427
BACK ↔ t2   0.034      t1   ↔ 8/9   0.399
t1   ↔ t2   0.031      t2   ↔ 8/9   0.425
```

**8/13 세 빌드는 XDC가 서로 다른데도 TVD 0.03으로 일치한다.** 홀로 다른 것은 8/9뿐.

### 2-4. 극성·비트순서 버그가 아님을 확인

원본/비트반전/니블역순/둘다 — 4가지 해석 전부에서 8/9은 3패턴 사슬, 8/13은 7패턴 비사슬.

### 2-5. 8/9 데이터의 자기 정합성 (기존 그림에서 확인)

`Markdown/fig/2026-08-12_thermometer_order.png` 패널 (d):
8/9 thermometer의 구간 체류 비율이 **CO 히스토그램**(`co_temp/co_histo_40*.csv`)의 폭 비율과
**1.6 ps 안에서 일치**한다.

| 구간 | thermometer | 히스토그램 폭 | 차이 |
|---|---|---|---|
| CO[1]→CO[3] (`%4==1`) | 55.2 % | 56.7 % | 0.8 ps |

## 3. Vivado routed 체크포인트 실측 — 80단 전수

대상: `TDC_v1/TDC_v1.runs/impl_1/tdc_test_top_routed.dcp` (2026-08-13 13:49, thermo 빌드)

### 3-1. CO[j] → FF.D 경로 (측정)

```
CO[0]  INTRASITE  FAST_MIN  29  FAST_MAX  37  SLOW_MIN  74  SLOW_MAX  91   x 80
CO[1]  INTRASITE  FAST_MIN  29  ...                          SLOW_MAX  91   x 80
CO[2]  INTRASITE  FAST_MIN  29  ...                          SLOW_MAX  91   x 80
CO[3]  ROUTED     FAST_MIN 104                               SLOW_MAX 336   x 79
CO[3]  INTRASITE  FAST_MIN 104                               SLOW_MAX 336   x  1
```

**320개 경로가 단 두 개의 값만 가진다. 산포 0.**

`ROUTE_STATUS`가 ROUTED든 INTRASITE든 지연이 같다 → **배선 때문이 아니라 슬라이스 내부
CO[3]→DFF.D 경로 자체가 느리다.** (INTRASITE 1건은 다음 단 CI를 구동하지 않는 마지막 단으로 추정.)

**차이 75 ps(FAST 코너) ~ 245 ps(SLOW 코너).** LSB 16.722 ps 기준 **4.5 ~ 14.7 탭**.

> **CARRY4 탭 4개 중 CO[3]만 자기 FF까지 구조적으로 밀려 있다. 80단 전부 동일.**
> `%4` 4그룹 구조의 유력한 물리적 원인 후보. **다만 확정은 아니다** — 히스토그램 인덱스는
> popcount(도착 **순위**)라서, 위치 3이 4~15순위 밀리면 순위↔물리위치 대응이 섞인다.

### 3-2. taps_sampled → taps_sampled_d1 홉 (측정)

```
FAST_MIN 234~389 ps,  SLOW_MAX 738~1100 ps,  전부 ROUTED
SLICE_X42Y{k} → SLICE_X43Y{k}
```

탭마다·스테이지마다 다르다. **그러나 FF→FF 동기 경로이고 5000 ps 주기에서 최악 1100 ps를
써도 여유가 3900 ps 남는다.** 값을 흐트러뜨릴 수 없다.

### 3-3. CARRY4 내부 아크는 Vivado가 값을 주지 않는다 ★

```
NAME       u_carry4/CYINIT --> u_carry4/CO[0] [combinational]
IS_DISABLED          1
DELAY_FAST_MIN_RISE  0.000     (12개 지연 속성 전부 0.000)
```

`set_false_path` 때문에 아크가 비활성이라 **도착 순서를 실제로 정하는 내부 지연에 대해
Vivado는 아무 정보도 주지 않는다.**

### 3-4. 타일 구조 확인 (측정)

```
X42Y0 : CLBLM_R_X29Y0    ┐ 같은 CLB 타일 (SLICEM + SLICEL)
X43Y0 : CLBLM_R_X29Y0    ┘  ← taps_sampled_d1
X42Y1 : CLBLM_R_X29Y1       ← 캐리 다음 단
X44Y0 : CLBLL_L_X30Y0       ← 옆 CLB (다른 타일)
```

디바이스 뷰가 한 타일의 두 슬라이스를 위아래로 그려서 캐리가 건너뛰는 것처럼 보이지만,
**캐리 체인은 X42 컬럼만 타고 올라가며 X43을 지나지 않는다.**

## 4. thermo 빌드는 측정 빌드와 다른 회로다

### 4-1. 원인 규명

`probe3`에 붙어 있던 `final_timestamp_ps`를 떼고 `dbg_thermo`를 넣으면:

`final_timestamp_ps`(64비트)의 소비처는 **ILA `probe3` 하나뿐**이었다
(`RTL/tdc_test_top.v` 258·397줄). 이를 떼는 순간 다음이 통째로 최적화되어 사라진다:

- `u_lut_rom` (`tdc_calib_rom`, 320×13 BRAM)
- `mul_L_d2` / `mul_H_d2` (`(* use_dsp *)` DSP48)
- `coarse_total_ps_d3` 48비트 가산, `final_absolute_time_ps_reg` 48비트 감산
- 이들을 먹이는 5단 파이프라인 레지스터

`capture_trigger`(← `capture_arm`, `prev_loop_cnt`)도 `probe0` 하나뿐이라 함께 죽는다.
`aligned_coarse`(32비트)는 원래부터 소비처가 없었다.

죽은 셀들이 정확히 `pblock_pipeline`(`SLICE_X42Y0:SLICE_X47Y100`, 필터 `*mul*`·`*_d2~d5_reg*`)의
내용물이라 **pblock 기둥이 비고 나머지 로직이 재배치된다.**

동시에 `dbg_valid = (|dbg_thermo) & ~(&dbg_thermo)` = 48입력 OR + 48입력 AND 리덕션
(**추정 약 22 LUT**)이 BEL로 고정된 `taps_sampled_d1[64..111]` 옆에 새로 생긴다.

- CO[j]→FF.D 지연은 80단 전부 동일 (배치·배선과 무관)
- FF 4개는 같은 슬라이스 → 클럭 스큐 0
- d1 홉은 여유 3900 ps → 값에 영향 없음
- 그럼에도 8/6 빌드(군집 B)와 8/13 빌드(군집 A)는 체인 전체가 5 % 다르고 `%4` 분포도 다르다
- thermometer도 히스토그램과 **같은 방향으로** 함께 이동

**측정되지 않은 것**
- CARRY4 내부 아크 `CI→CO[j]` — `set_false_path`로 비활성(§3-3)

**가설 (미검증)**: 내부 지연은 배치가 아니라 **국소 전원(IR drop)**에 좌우되고, 주변 로직
배치가 바뀌면 함께 바뀐다. 체인 길이가 284 → 299탭(5 % 빨라짐)으로 변한 것이 정황.

**추가 정황 (측정)**: 링 오실레이터에 LOC 제약이 하나도 없어 빌드마다 주파수가 바뀐다.
```
plain  (co_histo_back.csv)   f_RO = 62.852 MHz
thermo (co_histo_error.csv)  f_RO = 65.850 MHz     (+4.8 %)
```
계산: `f_RO = ro_meas_cnt × 400 Hz` (10 ms 게이트, `ro_divider_cnt[1]` = RO의 1/4 주기).
다이 온도는 40.73 vs 41.10 °C로 작다. 통계 노이즈도 배제된다(차이가 포아송 오차의 평균
30배, 최대 432배).

**즉 지연선은 고정했지만 자극(hit 소스)은 방치돼 있다.** 빌드 간 비교를 엄밀히 하려면
RO도 LOC로 고정해야 한다. — **미결정 사항**
